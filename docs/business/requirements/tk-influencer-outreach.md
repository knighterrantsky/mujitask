# 达人建联表需求

更新时间：`2026-08-17`

- 入口任务：`tiktok_influencer_outreach_sync`
- 触发方式：定时任务、手动触发或 CLI
- 来源表：达人建联表
- 数据来源：FastMoss 商品详情页「商品关联视频」接口、FastMoss 视频详情 overview 接口
- 接口事实来源：[../../reference/fastmoss-known-interfaces.md](../../reference/fastmoss-known-interfaces.md)

## 1. 流程定位

达人建联表用于跟踪表内达人是否已经为指定商品发布带货视频，并持续刷新该达人对该 SKU 的视频数量、聚合播放量和代表视频链接。

系统只从达人建联表路由所配置视图中读取 `采集标签` 精确等于大写 `T` 的候选行，再按候选行中的 `SKUID` 和 `达人ID` 进行商品视频分页、视频索引沉淀和播放量刷新。候选范围是“配置视图中的记录 ∩ `采集标签=T`”，不绕过现有 `view_id` 扩大到物理表全部记录。商品视频分页窗口仅以这些 `T` 行的飞书字段自动计算，不接受任务参数覆盖，也不新增本地游标表；人工修改飞书 `检查时间` 或其他流程写入该字段导致的窗口异常属于业务接受风险。

## 2. 当前已澄清需求

1. 表中 `SKUID` 按当前业务理解等同于 FastMoss 商品 `product_id`。
2. 表中 `达人ID` 当前按 FastMoss/TikTok `unique_id` 使用，不按 FastMoss 数值型 `uid` 使用。
3. 匹配 FastMoss 商品关联视频记录时，使用 `row.unique_id` 或 `row.author.unique_id` 与飞书 `达人ID` 比对。
4. `采集标签` 是飞书表的单选配置前提，业务值为大写 `T` 或 `F`。只有字段值精确等于 `T` 的行才是候选行；Runtime 只校验字段名存在，不在本 workflow 内扩展通用飞书字段类型校验。
5. 飞书读取阶段必须在配置视图范围内按 `采集标签=T` 做服务端过滤；所有入口都使用固定逻辑路由 `feishu://mujitask/tk_influencer_outreach`，由部署配置 `TK_INFLUENCER_OUTREACH` 解析实际表和视图。调用方不得传入原始飞书 URL、其他 alias、`table_id/view_id` 或嵌套路由/过滤参数改写候选范围和标签条件。`F`、空值、字段值缺失、小写 `t` 或其他值都不读取、不处理、不写回且不进入统计，它们之间不区分跳过原因。
6. 系统必需字段为：`采集标签`、`SKUID`、`达人ID`、`视频链接`、`视频发布时间`、`检查时间`、`播放量(W)`、`视频数量`、`更新时间`。飞书服务端负责过滤记录，返回记录在本地只保留这些固定字段。
7. 任一必需字段缺失或改名时，任务必须失败并返回字段缺失错误，不得静默以零候选成功。字段存在但没有任何 `T` 行时，任务以成功空操作结束。
8. 只对飞书返回的 `T` 行校验 `SKUID` 和 `达人ID`；任一字段为空时直接跳过并记录原有缺失原因。
9. 当前阶段 `SKU + creator_unique_id` 在达人建联表内唯一，不存在同一 SKU 同一达人多行写回。
10. 候选行按 `SKUID` 聚合。同一 SKU 同时存在 `T` 行和非 `T` 行时，该 SKU 可由 `T` 行触发一个 SKU 商品视频索引 job，在自动计算的窗口内完整分页并沉淀事实，但只为 `T` 行派发达人刷新与飞书写回。
11. 当 SKU 下存在 `视频链接` 为空的 `T` 行时，已有 `视频链接` 的 `T` 行不参与商品视频分页窗口计算，但仍参与后续播放量和视频数量刷新。
12. 商品视频分页窗口只能由 `T` 行的 `检查时间`、`更新时间` 和 `视频链接` 自动计算。调用方不得传入 `source_record_ids`、`force_full`、顶层 `start_date`、顶层 `end_date` 或 `trigger_date`；系统以 task request `created_at` 按 `Asia/Shanghai` 自然日生成唯一任务日期，供各 stage 重用。
13. 任务后续 stage 使用 `feishu_table_read` result 中的归一化 `T` 候选结果快照继续执行；执行中将标签从 `T` 改为任意非 `T` 值只对下一次任务生效。
14. 标签从任意非 `T` 值改回 `T` 时，该行重新进入当前 SKU 的自动窗口计算，但在不新增标签切换游标的前提下不保证覆盖整个非 `T` 停用期。改为任意非 `T` 值时不清空飞书历史字段或已沉淀事实。
15. `检查时间` 只在最终聚合结果没有可写 `视频链接` 且飞书原行没有 `视频链接` 时写回，表示该 SKU + 达人本次已检查但没有可写视频。
16. `更新时间` 表示飞书行数据本次实际发生刷新字段写入变化；仅写 `检查时间` 时不更新 `更新时间`。
17. `/api/goods/v3/video` 只用于发现 SKU 关联视频，并沉淀 `product + creator + video` 关系。
18. `/api/video/overview` 是每条视频播放量的最终统计来源；不使用商品视频列表接口的 `play_count` 作为最终播放量口径。
19. 同一 SKU + 达人可能存在多条视频，内部按全部已知视频 overview 播放量求和。
20. `播放量(W)` 是飞书数字字段，写入值为总播放量除以 `10000` 的 JSON 数字，例如总播放量 `19999` 写入 `1.9999`、`120345` 写入 `12.0345`；不得写入 `<1W`、`1W` 等文本。
21. 聚合结果存在可写 `视频链接` 时，`视频数量` 写入该 SKU + 达人全部已知视频数量；数量变化时更新。
22. 聚合结果存在可写 `视频链接` 时，`视频链接` 写入该 SKU + 达人播放量最高的视频 URL；最高播放视频变化时可以覆盖。
23. 聚合结果存在可写 `视频链接` 时，`视频发布时间` 写入该 SKU + 达人最早发布视频的发布时间；字段已有值时后续不更新。
24. 写回决策以 overview 全量采集后的最终聚合结果为主：如果聚合结果没有可写 `视频链接` 且飞书原行没有 `视频链接`，只写 `检查时间`；如果聚合结果没有可写 `视频链接` 但飞书原行已有 `视频链接`，视为本地视频索引缺失并跳过该行。

## 3. 采集与匹配逻辑

正式流程：

1. 在读取记录前校验飞书表的全部必需字段名；任一字段缺失时立即失败。`采集标签` 的单选类型和 `T/F` 选项由飞书表配置保证，本 workflow 不扩展通用类型校验。
2. 在达人建联表路由配置的 `view_id` 范围内，向飞书发起精确 `采集标签=T` 服务端记录过滤查询；飞书返回记录后，本地归一化只保留：`采集标签`、`SKUID`、`达人ID`、`视频链接`、`视频发布时间`、`检查时间`、`播放量(W)`、`视频数量`、`更新时间`。若本地收到非 `T` 记录，视为过滤契约违反并立即失败，不计入业务统计。
3. 对返回的 `T` 行校验 `SKUID` 和 `达人ID`，跳过任一字段为空的行。
4. 按 `SKUID` 聚合剩余 `T` 行，避免按飞书行逐条请求 FastMoss 商品视频列表。非 `T` 行不参与分组、窗口计算或达人刷新。
5. 任务候选范围、商品视频窗口和任务日期不接受人工覆盖。调用方传入 `source_record_ids`、`force_full`、顶层 `start_date`、顶层 `end_date` 或 `trigger_date` 中的任意字段时，workflow 必须在派发任何 job 前结束为不可重试的契约失败。该检查允许 task request 已创建，不承诺在持久化前同步拒绝；系统以 task request `created_at` 按 `Asia/Shanghai` 自然日固定任务日期。
   正式 submit 只接受 `source_table_ref`、`reply_target`、`writeback_enabled` 和标准 Runtime 控制字段；`mock_fastmoss_*`、调用方分页上限、凭据变量名及其他未声明业务字段在创建 task request 前以 `invalid_outreach_task_payload` 拒绝。
   `writeback_enabled=false` 是发布验收使用的正式试运行模式：仍真实读取飞书、调用 FastMoss 并沉淀 Runtime/Fact 数据，但不得更新飞书记录；它不代表无副作用模拟。
6. 如果 SKU 下存在 `视频链接` 为空的 `T` 行，只使用这些无视频链接行计算商品视频分页窗口；该 SKU 下已有 `视频链接` 的 `T` 行不参与本次分页窗口计算：
   - 如果这些无视频链接行都没有 `检查时间`，本次对该 SKU 走全量商品视频分页，FastMoss 参数使用 `d_type=0`。
   - 如果这些无视频链接行存在 `检查时间`，取其中最早的 `检查时间 - 1 天` 作为 `start_date`，任务当天作为 `end_date`，执行增量商品视频分页。
7. 只有当 SKU 下全部 `T` 行都有 `视频链接` 时，才使用这些 `T` 行的 `更新时间` 计算新内容发现窗口，用于发现新视频并刷新 `视频数量` 和播放量：
   - 如果这些行存在 `更新时间`，取最晚的 `更新时间 - 1 天` 作为 `start_date`，任务当天作为 `end_date`，执行增量商品视频分页。
   - 如果这些行都没有 `更新时间`，本次对该 SKU 走全量商品视频分页，FastMoss 参数使用 `d_type=0`。
8. 商品视频分页使用 `pagesize=5`。
9. 将 FastMoss 商品视频列表返回记录归一化为：
   - `product_id`
   - `creator_unique_id`
   - `video_id`
   - `create_date`
   - `video_url`
10. 商品视频分页完成后，只按本轮 `T` 候选行中的每一行 `SKUID + 达人ID` 拆分刷新任务；当前阶段该组合在表内唯一。
11. 每个刷新任务以飞书 `T` 行快照为依据，从数据库检索该 SKU 下该达人的全部已知视频。
12. 如果该 SKU + 达人没有已知视频，则最终聚合结果没有可写 `视频链接`：
   - 飞书原行没有 `视频链接` 时，只写回 `检查时间`，不写其他字段。
   - 飞书原行已有 `视频链接` 时，视为本地视频索引缺失，跳过该行，不写 `检查时间` 或其他字段。
13. 如果该 SKU + 达人有 M 条已知视频，必须对 M 条 video 全部调用 `/api/video/overview` 成功，并持久化视频播放量快照后，才聚合视频数量、总播放量、最高播放视频和最早发布时间。
14. 聚合完成后，如果最高播放视频 URL 为空：
   - 飞书原行没有 `视频链接` 时，只写回 `检查时间`，不写 `视频链接`、`视频发布时间`、`播放量(W)`、`视频数量` 或 `更新时间`。
   - 飞书原行已有 `视频链接` 时，视为本地视频索引缺失并跳过该行。
15. 聚合完成后，如果最高播放视频 URL 不为空，则按聚合结果写回 `视频链接`、`播放量(W)`、`视频数量`，并在 `视频发布时间` 为空时写入最早发布时间。
16. SKU + 达人刷新任务内完成飞书当前行写回；不再单独拆一个最终批量写回阶段。
17. 任意 video overview 或飞书写回失败时，不写半截聚合结果，刷新任务重试；三次失败后跳过该 SKU + 达人行并进入汇总统计。
18. 商品视频列表抓取失败时，该 SKU 对应达人行不写任何检查结果，等待后续重试。

## 4. 视频链接生成结论

FastMoss 商品关联视频接口本身未直接返回完整 TikTok 视频 URL，但已返回生成官方 TikTok 视频链接所需的稳定字段：

- `video_id`
- `row.unique_id` 或 `row.author.unique_id`

因此当前可以基于已有接口字段生成目标视频链接：

```text
https://www.tiktok.com/@{unique_id}/video/{video_id}
```

示例：

```text
https://www.tiktok.com/@heidiann__/video/7641370220849859854
```

当前判断：在不要求从 FastMoss 返回体直接读取 URL 的前提下，已有商品视频列表字段足够生成飞书 `视频链接` 字段。

聚合结果存在可写 `视频链接` 时，`视频链接` 的写回口径为该 SKU + 达人播放量最高的视频 URL。最高播放视频由 `/api/video/overview` 播放量决定，播放量相同时按视频发布时间和 `video_id` 稳定选择。聚合结果没有可写 `视频链接` 时，只写 `检查时间`。

## 5. 聚合字段写回口径

1. `播放量(W)`：内部统计仍保留该 SKU + 达人全部已知视频的 overview 原始播放量总和；飞书写入值为原始总和除以 `10000` 后的 JSON 数字。
2. `播放量(W)` 不写展示文本；小于 10000 的总播放量写 `0` 到 `1` 之间的数字，大于等于 10000 的总播放量写对应 W 数值，飞书数字字段格式负责展示小数位。
3. `视频数量`：聚合结果存在可写 `视频链接` 时，写入该 SKU + 达人全部已知视频数量；如果昨天为 11 条，今天新发现 1 条，则更新为 12。
4. `视频链接`：聚合结果存在可写 `视频链接` 时，写入该 SKU + 达人播放量最高的视频 URL；最高播放视频变化时可以覆盖原值。
5. `视频发布时间`：聚合结果存在可写 `视频链接` 时，写入该 SKU + 达人最早发布视频的发布时间；只在字段为空时写入，后续不更新。
6. `检查时间`：聚合结果没有可写 `视频链接` 且飞书原行没有 `视频链接` 时写回；聚合结果存在可写 `视频链接` 时不更新该字段；聚合结果没有可写 `视频链接` 但飞书原行已有 `视频链接` 时跳过该行。
7. `更新时间`：只在本次实际写入 `视频链接`、`视频发布时间`、`播放量(W)` 或 `视频数量` 时更新；仅写 `检查时间` 时不更新该字段。
8. 若聚合结果与飞书现有值一致，且无需写入 `检查时间`，则不写该行。

## 6. 分行写回规则

1. 聚合结果没有可写 `视频链接`，且飞书原行没有 `视频链接`：
   - 只写回 `检查时间`。
   - 不写回 `视频链接`、`视频发布时间`、`播放量(W)`、`视频数量` 或 `更新时间`。
2. 聚合结果没有可写 `视频链接`，但飞书原行已有 `视频链接`：
   - 视为本地视频索引缺失或历史视频尚未沉淀。
   - 跳过该行，不写 `检查时间` 或其他字段。
3. 聚合结果存在可写 `视频链接`：
   - 不更新 `检查时间`。
   - 写回或刷新 `播放量(W)`、`视频数量`。
   - `播放量(W)` 写入总播放量除以 `10000` 后的 JSON 数字，不写 `<1W` 或 `nW` 文本。
   - 最高播放视频变化时更新 `视频链接`。
   - `视频发布时间` 只在字段为空时写入最早发布时间；已有值不更新。
4. 视频 overview 必须在同一 SKU + 达人下全部成功后才写聚合结果；失败时不写半截结果，重试三次后跳过该行。
5. 飞书写回失败视为当前 SKU + 达人刷新任务失败并重试；重试耗尽后跳过该行。

## 7. 可行性验证结论

当前需求已完成关键可行性验证：

1. FastMoss 商品关联视频接口可按商品查询视频列表。
2. 接口支持全量分页参数 `d_type=0`。
3. 接口支持自定义日期区间。
4. 接口支持按发布时间倒序排序。
5. 接口支持分页，并返回 `data.total`。
6. 接口返回 `unique_id`，可用于匹配飞书 `达人ID`。
7. 接口返回 `video_id` 和 `create_date`，可用于生成视频链接和写入视频发布时间。
8. `/api/video/overview` 返回单条视频维度播放量，可用于持久化视频播放量快照并进行达人聚合。

## 8. 仍需实现阶段确认的点

1. 飞书 `SKUID` 是否在所有实际行中都稳定等同于 FastMoss `product_id`。
2. 飞书 `达人ID` 是否在所有实际行中都按 TikTok/FastMoss `unique_id` 填写。
3. `create_date` 只有日期粒度；如果后续需要精确到时分秒，需要另找视频详情来源。
4. 多取 1 天后可能重复命中历史视频，依赖数据库视频关系去重和播放量快照追加避免重复统计。
5. 人工修改飞书 `检查时间` 可能造成分页窗口过大或过小，该风险按当前需求接受。

## 9. 验收口径

1. `采集标签` 作为飞书表配置前提必须为单选字段，候选值只按大写 `T` 精确匹配；Runtime 验收只校验必需字段名，不校验飞书字段类型或选项元数据。
2. 飞书服务端只返回配置视图中 `采集标签=T` 的行；`F`、空值和其他值不读取、不处理、不写回且不进入汇总统计。
3. 任一必需读取字段缺失或改名时任务失败；全部字段存在但没有 `T` 行时，任务以成功空操作结束。
4. 汇总中的“读取飞书行数”名称保持不变，数值为飞书过滤后返回的 `T` 行数；不输出非 `T` 行数。
5. 仅对 `T` 行校验 `SKUID` 和 `达人ID`；缺失行按现有 `missing_product_id` 或 `missing_creator_unique_id` 原因跳过并统计。
6. `source_record_ids`、`force_full`、顶层 `start_date`、顶层 `end_date` 和调用方提供的 `trigger_date` 不再是任务输入；请求中只要出现任一已移除字段，即使值为空也必须明确拒绝，不得静默忽略。`source_table_ref` 归一化后必须是固定逻辑路由 `feishu://mujitask/tk_influencer_outreach`；原始 URL、其他 alias 或显式表/视图标识必须以契约错误拒绝。
7. 只有 `T` 行参与 SKU 分组、分页窗口计算、达人刷新和飞书写回。
8. 同一 SKU 有 `T` 行和非 `T` 行时，该 SKU 因 `T` 行派发一个商品视频索引 job；job 可沉淀该 SKU 在自动窗口内完整分页返回的全部视频事实，但只为 `T` 行派发达人刷新和飞书写回。
9. 只有 `T` 且 `视频链接` 为空的达人行参与无链接分页窗口计算。
10. 当 SKU 下存在 `视频链接` 为空的 `T` 行时，已有 `视频链接` 的 `T` 行不参与商品视频分页窗口计算，但仍参与后续播放量和视频数量刷新。
11. 当参与窗口计算的无视频链接 `T` 行都没有 `检查时间` 时，SKU 使用 `d_type=0` 全量分页。
12. 当参与窗口计算的无视频链接 `T` 行存在 `检查时间` 时，SKU 使用最早 `检查时间 - 1 天` 到任务当天的日期区间分页。
13. 只有当 SKU 下全部 `T` 行都有 `视频链接` 且存在 `更新时间` 时，SKU 才使用最晚 `更新时间 - 1 天` 到任务当天的日期区间分页，用于发现新增视频。
14. 当 SKU 下全部 `T` 行都有 `视频链接` 且都没有 `更新时间` 时，SKU 使用 `d_type=0` 全量分页。
15. 行从任意非 `T` 值改回 `T` 后重新进入当前 SKU 的自动窗口计算；不新增标签切换游标，因此不承诺覆盖整个非 `T` 停用期。改为任意非 `T` 值不清空历史字段或事实数据。
16. 任务开始后按 `feishu_table_read` result 中的归一化 `T` 候选结果快照执行，执行中的标签修改从下一次任务起生效；该口径不强制开启 raw artifact snapshot。
17. `播放量(W)` 的原始统计来源是 `/api/video/overview`，不是 `/api/goods/v3/video` 的 `play_count`。
18. 内部统计值为 SKU + 达人维度全部已知视频原始播放量总和。
19. `播放量(W)` 飞书写入值为原始总播放量除以 `10000` 后的 JSON 数字，不写 `<1W` 或 `nW` 文本。
20. 飞书写回决策先看最终聚合结果是否存在可写 `视频链接`；仅在聚合结果没有可写 `视频链接` 时，才需要参考飞书原行是否已有 `视频链接`。
21. 聚合结果没有可写 `视频链接` 且飞书原行没有 `视频链接` 时，只写 `检查时间`，不写 `视频链接`、`视频发布时间`、`播放量(W)`、`视频数量` 或 `更新时间`。
22. 聚合结果没有可写 `视频链接` 但飞书原行已有 `视频链接` 时，跳过该行，不写 `检查时间` 或其他字段。
23. 聚合结果存在可写 `视频链接` 时，刷新 `播放量(W)` 和 `视频数量`，并在最高播放视频变化时更新 `视频链接`。
24. `视频数量` 写入 SKU + 达人维度全部已知视频数量，并在数量变化时写回。
25. `视频链接` 写入 SKU + 达人维度播放量最高的视频 URL，最高播放视频变化时可以覆盖旧值。
26. `视频发布时间` 取 SKU + 达人维度最早发布视频时间；字段已有值时后续不更新。
27. `检查时间` 只在聚合结果没有可写视频链接且飞书原行没有视频链接时更新；聚合结果存在可写视频链接时不更新该字段。
28. `更新时间` 只在实际写入 `视频链接`、`视频发布时间`、`播放量(W)` 或 `视频数量` 时更新；仅写 `检查时间` 时不更新该字段。
29. 达人建联表的 `粉丝数(W)` 不在本 workflow 读写范围；本次变更只增加采集标签门禁并删除人工候选/窗口覆盖输入，不新增达人详情请求或粉丝数写回。
30. SKU + 达人刷新任务内完成 overview 采集、快照、聚合和飞书写回；不单独拆最终批量写回阶段。
31. 同一 SKU + 达人的任意视频 overview 失败时，不写该行聚合结果，重试三次后跳过。
32. 本实现阶段不新增本地游标表；workflow、contract 和测试需要与上述口径保持一致。

## 10. 兼容口径

1. 本次候选集和任务输入语义发生破坏性变更；`task_code`、`workflow_code`、stage code 和 job code 保持不变，workflow 使用达人建联专属的新 `contract_revision`。
2. 本次采用一次性硬切，不保留 `source_record_ids`、`force_full`、顶层 `start_date/end_date` 或调用方 `trigger_date` 的兼容分支。请求中只要出现任一已删除字段，即使值为空，也必须在派发任何 job 前以不可重试的契约错误终止。
3. 发布和回退前必须停止该任务的新提交并完成旧 request、API job 和 browser fallback execution 的 drain；错误外壳、revision、取消、验空与回退步骤以[达人建联检查 Workflow 设计](../../arch/workflow-influencer-outreach-design.md)和发布 runbook 为准。
