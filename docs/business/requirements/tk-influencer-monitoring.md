# TK 达人监控需求

更新时间：`2026-07-25`

- 状态：已确认，待实现
- 入口任务：`monitor_tk_influencers`
- 触发方式：每天一次定时任务
- 来源表：`TK竞品收集`
- 目标表：`TK达人监控目标表`
- 字段口径：本文件独立定义目标表字段、数据来源、合并规则和覆盖规则，不依赖其他达人流程。

## 1. 流程定位

`TK达人监控` 是一个全新的独立流程。它每天扫描 `TK竞品收集` 中的全部有效 SKU，通过 FastMoss 商品关联视频发现达人，把“商品关联视频近 28 天销量”超过阈值的达人写入专用目标表。

本流程用于持续发现和沉淀有实际带货表现的达人。它只读取 `TK竞品收集`、FastMoss 数据和 `TK达人监控目标表` 自身记录；不读取其他达人业务表，也不读写 `达人查找状态`。

目标表当前没有历史记录，首次运行从空表开始创建达人记录。后续每天重复运行时，`关联商品销量` 只保留系统历史观测到的最高“近 28 天销量”，低值不覆盖高值。

## 2. 业务术语

| 术语 | 本流程口径 |
| --- | --- |
| SKU | `TK竞品收集` 中能够解析为 FastMoss `product_id` 的 `SKU-ID` |
| 商品关联视频 | FastMoss 商品详情页“商品关联视频”范围内的视频 |
| 近 28 天销量 | 商品关联视频行上的“销量（近28天）”，是视频与商品关系的 28 天窗口指标 |
| 达标视频 | `近 28 天销量 > min_video_sales_28d` 的视频 |
| 达标商品关系 | 同一 SKU 下，某达人至少存在一条达标视频 |
| 本次达人最高销量 | 本次任务中，同一达人跨所有达标商品关系的最高近 28 天销量 |
| 历史最高销量 | 目标表已有 `关联商品销量` 与本次达人最高销量中的较大值 |

## 3. SKU 来源与视频筛选

1. 每次任务读取 `TK竞品收集` 中全部能够解析出有效 SKU 的记录。
2. `达人查找状态` 不参与筛选；无论为空、`待查找`、`处理中`、`已完成` 或 `失败重试`，都按 SKU 进入本流程。
3. `商品状态` 不参与筛选；包含正常商品、已下架商品和区域不可售商品。
4. 相同 SKU 在来源表出现多次时，只请求一次 FastMoss 商品关联视频；不同来源行上的商品图按 `product_id + attachment/asset identity` 去重合并，节日按标准化文本值去重合并。
5. 视频范围固定为：
   - 投流情况：全部；
   - 发布时间：全部；
   - 排序字段：销量（近28天）；
   - 排序方向：倒序。
6. 不按视频发布时间限制为近 28 天；“全部视频”与“销量指标使用近 28 天窗口”是两个独立口径。
7. 入选阈值由任务参数 `min_video_sales_28d` 控制，默认值为 `50`，判断条件为严格大于：
   - 销量 `50`：不入选；
   - 销量 `51`：入选。
8. 近 28 天销量为空、无法解析或不是有效数字的视频不入选，也不能伪造为 `0`。
9. 粉丝数不参与达人筛选。粉丝数为任意值的达人都可以入选；入选后从 FastMoss 达人详情采集并按第 5 节规则更新 `粉丝数`。

## 4. 达人去重与销量聚合

达人销量按以下顺序聚合：

1. 同一视频重复返回时，先按视频稳定身份去重。
2. 同一 SKU 下，同一达人有多条达标视频时，只取其中近 28 天销量的最大值。
3. 同一达人同时命中多个 SKU 时，本次任务的 `关联商品销量` 取这些 SKU 最大值中的最大值，不求和。
4. 目标表不存在该达人时，以本次达人最高销量创建记录。
5. 目标表已存在该达人时：
   - 本次达人最高销量大于已有值：覆盖为本次值；
   - 本次达人最高销量等于已有值：销量不变；
   - 本次达人最高销量低于已有值：销量不变。
6. 后续某天达人没有达标视频、销量下降到阈值以下或 FastMoss 当前返回空列表时，不删除达人、不清零，也不降低已有 `关联商品销量`。

等价业务规则为：

```text
SKU + 达人销量 = max(该 SKU 下该达人的达标视频近28天销量)
本次达人销量 = max(该达人本次命中的全部 SKU + 达人销量)
目标表关联商品销量 = max(目标表已有值, 本次达人销量)
```

## 5. 目标表写入与字段维护

目标表保持一人一行。`达人ID` 使用 FastMoss canonical `creator_id` 的标准化文本，也是唯一 upsert 键；商品关联视频行只有稳定 `uid` 时，由本流程 mapper 将其归一化为 canonical `creator_id`。`unique_id`、昵称和主页名称只作为辅助信息，不得作为 upsert 键。无法生成稳定 `达人ID` 的候选不写入目标表并记录失败原因。

目标表只读取自身已有行来执行销量 `max`、关联字段集合合并和字段 diff，不从其他达人业务表复制记录或字段值。

系统自动维护字段及规则如下：

| 字段 | 本流程写入规则 |
| --- | --- |
| `达人ID` | 创建必填，也是唯一 upsert 键；后续不修改身份 |
| `带货商品图` | 合并所有达标商品关系对应的 `TK竞品收集.图片`，按 `product_id + attachment/asset identity` 去重追加，不删除已有有效图片 |
| `关联节日` | 合并所有达标商品关系对应来源行的节日，标准化文本后做集合并集，不删除已有值 |
| `关联商品销量` | 写入历史观测最高近 28 天销量，只升不降，不累加 |
| `达人头像` | 来自 FastMoss 达人详情；同步为稳定头像附件引用，有效新头像可刷新，空值不清空目标表已有头像 |
| `粉丝数` | 来自 FastMoss `follower_count`，不参与筛选；详情采集成功且数值有效时刷新，空值或非法值不覆盖；写入飞书时，`>=10000` 除以 `10000` 后按四舍五入到最近整数并显示为 `xW`，`<10000` 显示为 `小于1W` |
| `28天视频数` | 来自 FastMoss `aweme_28d_count`；详情采集成功且数值有效时刷新，空值或非法值不覆盖 |
| `带货视频 GMV` | 来自 FastMoss `video_sale_amount`；详情采集成功且数值有效时刷新，空值或非法值不覆盖；展示规则与 `粉丝数` 相同 |
| `带货直播 GMV` | 来自 FastMoss `live_sale_amount`；详情采集成功且数值有效时刷新，空值或非法值不覆盖；展示规则与 `粉丝数` 相同 |
| `合作店铺` | 来自 FastMoss `cooperation_shops`；与目标表该达人已有店铺做集合并集，相同店铺不重复，仅写入飞书字段中已配置的店铺选项；未知选项跳过并记录 warning |
| `达人联系方式` | 来自 FastMoss 达人联系方式；有多个时优先邮箱，否则取第一个有效联系方式；空值不覆盖已有内容 |
| `记录日期` | 首次创建达人记录时写入，后续不覆盖 |
| `更新日期` | 首次创建时写入；后续仅在任一系统维护字段实际发生变化时刷新 |

补充规则：

1. 某 SKU 对应的达人销量虽然低于该达人已有历史最高值，但只要该 SKU 下仍存在销量严格大于阈值的达标视频，该 SKU 的商品图和节日仍参与去重合并。
2. 某 SKU 下该达人的所有视频都未超过阈值时，该 SKU 不形成达标商品关系，其商品图和节日不因本流程写入该达人行。
3. 合作店铺、达人头像、粉丝数、28 天视频数、GMV 和联系方式均从本次 FastMoss 达人详情与目标表该达人已有行计算，具体规则以上表为准。
4. `合作商品数`、公式字段、历史沉淀字段和人工运营字段不纳入本流程自动维护范围。
5. 如果本次计算结果与目标表现有字段完全一致，则不写该达人行，也不刷新 `更新日期`。

## 6. 任务参数与执行频率

顶层任务至少支持以下业务参数：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `min_video_sales_28d` | 非负整数 | `50` | 达标视频阈值，使用严格大于判断 |

执行规则：

1. 正常业务频率为每天一次。
2. 后续由 OpenClaw 定时任务触发 `monitor_tk_influencers`。
3. OpenClaw 的具体 cron 表达式、环境路由和部署配置不属于本需求范围。
4. 同一天重复执行相同阈值的任务必须保持幂等，不重复创建达人，不重复追加相同商品图、节日或店铺，也不重复累加销量。

## 7. 空结果、失败与部分成功

1. 某 SKU 没有关联视频，或有关联视频但没有达标视频，视为该 SKU 正常处理完成，候选达人数量为 `0`。
2. 已下架或区域不可售商品仍正常请求 FastMoss；FastMoss 返回空列表时按正常空结果处理。
3. 某 SKU 的 FastMoss 请求失败时，只影响该 SKU；其他 SKU 继续处理，任务允许部分成功。
4. 某达人的详情采集或目标表写入失败时，只影响该达人；其他达人继续处理。
5. 来源表读取整体失败、目标表无法读取或系统级配置不可用时，任务失败，不能把未处理记录计为成功。
6. 任一失败都不能写入半截达人数据；重试耗尽后保留可审计的 SKU、达人和失败原因摘要。
7. 本流程不向 `TK竞品收集` 回写 `达人查找状态`、`商品状态` 或其他来源字段。

## 8. 不在本期范围

本期不包含：

1. 读取、写入或调用其他达人业务表、workflow、job 或业务字段 contract。
2. 为来源 SKU 新增、重置或回写 `达人查找状态`。
3. 按粉丝数筛选达人。
4. 限制视频发布时间为近 7 天、近 28 天、近 90 天或自定义日期范围。
5. 因销量下降而降低、清零或删除目标表记录。
6. 修改目标表已有字段集合或新增业务字段。
7. 从其他达人业务表迁移历史数据；目标表从当前空表开始沉淀。
8. 固定 Base URL、`table_id`、`view_id` 或测试/生产环境差异；逻辑表到真实飞书表的映射由后续部署配置解决。
9. 配置和发布 OpenClaw 定时任务。

## 9. 验收口径

1. `TK竞品收集` 中所有有效 SKU 都会进入候选，不受 `达人查找状态` 限制。
2. `商品状态=已下架/区域不可售` 的有效 SKU 仍会请求商品关联视频。
3. 相同 SKU 多行时只执行一次商品视频请求，来源商品图按 `product_id + attachment/asset identity` 去重、节日按标准化文本值去重合并。
4. 商品关联视频查询使用“投流情况全部、发布时间全部、近 28 天销量倒序”的业务口径。
5. 视频近 28 天销量等于 `50` 时不入选，等于 `51` 时入选。
6. 修改 `min_video_sales_28d` 后，任务按新阈值筛选；未传参数时稳定使用默认值 `50`。
7. 达人粉丝数不影响入选结果。
8. 同一 SKU 下同一达人有销量 `60` 和 `90` 的两条达标视频时，该 SKU + 达人结果为 `90`。
9. 同一达人在 SKU-A 的结果为 `90`、SKU-B 的结果为 `120` 时，本次达人结果为 `120`。
10. 同一达人首次出现时，目标表只创建一行，并写入 `达人ID`、本次最高销量和其他可用自动维护字段。
11. 目标表已有销量 `80`、本次最高销量 `120` 时，更新为 `120`。
12. 目标表已有销量 `120`、本次最高销量 `80` 时，保持 `120`。
13. 目标表已有销量 `120`、后续任务没有发现该达人达标视频时，保持原记录和销量，不删除、不清零。
14. 同一达人命中多个达标 SKU 时，目标表仍保持一人一行。
15. 某个仍达标的 SKU 销量低于达人已有最高值时，销量不降低，但该 SKU 的商品图和节日仍按本文件定义的去重规则补充。
16. 某 SKU 下达人没有任何视频超过阈值时，该 SKU 不向该达人行追加商品图或节日。
17. 相同商品图、节日或合作店铺不会重复写入。
18. 达人联系方式为空时，不使用空值覆盖已有联系方式。
19. 新建达人时写入 `记录日期` 和 `更新日期`；后续没有实际字段变化时不刷新 `更新日期`。
20. 某 SKU 没有视频或没有达标达人时，该 SKU 以正常空结果进入汇总。
21. 单个 SKU 或达人失败时，其他 SKU 和达人可以继续成功，最终任务明确返回部分成功计数和失败摘要。
22. 本流程不会修改 `TK竞品收集` 的任何字段。
23. 同一天相同参数重复执行不会重复创建达人、重复追加关联字段或增加 `关联商品销量`。

## 10. 变更影响边界

本流程文档可独立变更：

1. 商品关联视频的业务筛选范围。
2. `min_video_sales_28d` 的默认值和比较规则。
3. 单 SKU、跨 SKU 和跨任务的达人销量聚合规则。
4. 目标表关联字段的合并和覆盖策略。
5. 本流程的空结果、部分成功和验收口径。

以下变更需要同步更新主需求文档和机器契约：

1. 新增、删除或改变目标表字段含义。
2. 修改 `达人ID` 唯一键口径。
3. 修改达人画像字段的数据来源、展示或覆盖规则。
4. 修改正式任务名称、来源表或目标表逻辑引用。
5. 改变本流程独立 workflow、job 或目标字段 contract 的边界。
